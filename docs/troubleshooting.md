# 常见问题与排查

先明确失败发生在哪一步：Azure 注册、创建资源、本机启动、连接 Azure，还是生成/播放。错误原因不一定都是额度不足。

## 注册和创建资源

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 小额银行卡交易失败 | CVV、有效期、账单地区、卡种、境外线上支付权限 | 联系发卡行查询拒绝原因，不反复盲目提交 |
| 小额冻结后仍注册失败 | 银行预授权和 Azure 注册是两个结果 | 看微软注册结果，按官方故障页排查 |
| 只看到门户，没有可用订阅 | 当前账号、目录及注册是否完成 | 打开订阅页确认 Active |
| 搜不到 Speech | 是否只搜索了已有资源 | 改到创建资源的市场搜索；用教程直达入口 |
| 没有 F0 | 产品类型、订阅、现有 F0 资源和可用区域 | 不先选 S0，查看官方支持或已有资源 |

入口：[注册排查](https://learn.microsoft.com/en-us/azure/cost-management-billing/troubleshoot-subscription/troubleshoot-azure-sign-up) · [创建 F0 教程](azure-f0-setup.md)。

## 本机打不开

| 现象 | 操作 |
| --- | --- |
| node 找不到 | 安装 Node.js 24 LTS，重新开终端并运行 node --version |
| Node 版本过旧 | 使用受支持的 22 或 24；doctor 会拒绝低于 22 的版本 |
| curl 找不到 | Windows 检查 curl.exe --version，其他系统使用系统包管理器安装 |
| macOS 双击失败 | 在已配置 Node 的终端进入目录，执行 sh start.sh |
| Windows 文件闪退 | 先解压全部文件，再在该目录运行 node scripts/start.mjs --doctor |
| PowerShell 禁止 npm.ps1 | 使用 node scripts/start.mjs --open 或 npm.cmd start，无需更改执行策略 |
| 浏览器连接被拒绝 | 确认终端仍在运行，网址端口是否与终端输出一致 |
| 4318 被占用 | 当前 free-tts 会尝试复用；其他程序占用时按安装教程更换 PORT |

完整启动方式见 [跨平台安装](local-setup.md)。

## 能打开，但连接 Azure 失败

- 验证失败或 HTTP 401：密钥和区域是否属于同一 Speech 资源，是否把订阅 ID 当作密钥。
- HTTP 403：资源状态、Azure 网络访问策略、权限或服务限制；查看 Azure 控制台，不直接认定余额不足。
- HTTP 404：核对区域代码和资源环境，本版对接国际版 Azure。
- HTTP 429：请求过快、特定音色容量不足或配额限制都有可能。先等待并换普通音色，再看实际用量。
- 超时：确认本机能访问 Azure；若需要代理，在设置好标准代理变量的同一终端重启工具，再试一次。持续失败检查网络、区域或 Azure 服务状态。

本地服务会隐藏上游原始错误中的敏感内容。报告问题时提供应用错误文字、操作系统、Node/curl 版本和复现步骤即可，不附密钥、身份证件、银行卡或完整私人文稿。

## 能连接，但生成或下载异常

- 按钮不可点击：先配置连接、选择音色并输入文字。超 3,000 字符或粗估超 8 分钟时缩短内容。
- 用少量文字成功、长文失败：分段生成，避免单次超时和云端 10 分钟音频上限。
- 下载的内容不完整：对照原文试听，长内容进一步缩短，尤其在慢语速下。
- 刷新后找不到结果：看「最近生成」。若缓存已清理或被 20 条上限淘汰，需要重新生成或找已下载文件。
- 修改参数后重新消耗额度：缓存键含完整文字、音色、语速、音调、区域和密钥；不同请求不会误用旧音频。
- 浏览器播放失败：下载 MP3，用本机播放器尝试；如果也是无声或损坏，用短文本换音色重试。

## 配置保存在哪里

在项目的 `.local/config.json`，缓存位于 `.local/audio/`；浏览器草稿位于本地站点的 localStorage。不要把这些内容随开源源码分享。只想移走密钥时用「连接设置 → 清除本机密钥」，不需要删除整个项目。

## 仍然失败

查看 [Azure 服务状态](https://azure.status.microsoft/) 和 [微软支持](https://azure.microsoft.com/en-us/support/)；准备问题报告前按 SECURITY.md 脱敏。当前 Windows/Linux 路线有脚本与测试配置，但是否在对应系统实机通过，以发布说明中的验证记录为准。
